# Template 3.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release hop-process-template 3.2.0: process lookup by `short_name`, generic `p_process_params`, and `tools/serasoft-sync.sh` / `tools/serasoft-verify.sh` to keep projects on a tagged template version, verified on Hop 2.16 and 2.19.

**Architecture:** Workflow changes are small XML edits to `src/template/` and `main.hwf`, tested end-to-end by a Docker lab (`tests/hop/`) that runs `hop-run` from the official `apache/hop` images against a PostgreSQL created by the template's Liquibase changelog, on a throw-away copy of the working tree. The sync/verify scripts are Bash, adapted from SeraSoft/airflow-dags, and tested with pytest against throw-away Git repositories (`tests/tools/`).

**Tech Stack:** Apache Hop 2.16.0 and 2.19.0 (images `apache/hop:2.16.0`, `apache/hop:2.19.0`, multi-arch), PostgreSQL 16 (`postgres:16-alpine`), Liquibase 4.33.0 (`liquibase/liquibase:4.33.0`), Bash 5 + GNU coreutils, Python 3 + pytest 8.

**Spec:** `docs/superpowers/specs/2026-11-05-template-sync-and-process-params-design.md`

## Global Constraints

- Branch: `feat/template-3.2.0` (already exists, holds the spec). One task = one commit (plus optional review-fixup commits). **Never push**: commits stay local until the controller opens the PR.
- Everything written (code, comments, docs, commit messages) is in English.
- Do **not** edit `db/liquibase/master.xml`: any change to an existing changeset changes its checksum and breaks `liquibase update` on existing databases.
- Do not edit `src/project/main/default/start.hwf`, `integration-tests/`, `.github/`.
- The lab never runs Hop on the repository itself: only on `tests/hop/work/copy` (git-ignored).
- `p_process_params` format, verbatim from the spec: `key=value` pairs separated by `;`; empty pieces ignored; split on the first `=`; key and value trimmed; key must match `^[A-Za-z_][A-Za-z0-9_.]*$`; a key given twice is an error; error message `ERROR: invalid p_process_params entry '<piece>': <reason>`; variables set at root workflow scope; precedence environment < `config/<short_name>.properties` < `p_process_params`; keys logged, values never.
- Template-owned paths, verbatim from the spec: `main.hwf`; `src/template/**`; `config/template-*.json`; `metadata/rdbms/integrations_db_*.json`; `metadata/workflow-log/workflow_log.json`; `metadata/pipeline-run-configuration/local.json`; `metadata/workflow-run-configuration/local.json`; `db/liquibase/**`; `tools/serasoft-verify.sh`; root `README.md` shipped as `src/template/README.md`. Seed files: `db/sqlite/data/integrations_db`, `integrations_db.config`, `integrations_db.logs`. Owned directories: `src/template/`, `db/liquibase/`.
- Root files in projects: `SERASOFT_VERSION` (`<tag> <commit>`), `SERASOFT_MANIFEST.sha256` (`sha256sum` format, sorted by path).
- Exit codes of the scripts: 0 success, 1 refused/failed, 64 usage, 66 (verify only) no manifest in the current directory.
- After each task: mark the checklist items of the task's GitHub issue as done (`gh issue edit <n> --body-file …`), see "Issues" below.

- [ ] **Step 1: Write `tests/hop/lab.sh`**

~~~bash
#!/usr/bin/env bash
# Throw-away lab for the template workflows: PostgreSQL 16 with integrations_db
# created by db/liquibase/master.xml, and hop-run from the official apache/hop
# images on a copy of the working tree (tests/hop/work/copy), never on the
# repository itself.
#
# Usage: tests/hop/lab.sh up | down | copy | sql "<query>"
#        tests/hop/lab.sh run <hop version> <file> [<params> [<variables>]]
#   run prints RC=<hop-run exit code>; the Hop log is tests/hop/work/hoprun.log.
set -euo pipefail
unset CDPATH
HERE="$(cd "$(dirname "$0")" && pwd -P)"
REPO="$(git -C "$HERE" rev-parse --show-toplevel)"
WORK="$HERE/work"
NET=hoptpl-net
PG=hoptpl-pg
PG_IMAGE=postgres:16-alpine
LB_IMAGE=liquibase/liquibase:4.33.0

usage() { echo "usage: tests/hop/lab.sh up | down | copy | sql <query> | run <hop version> <file> [<params> [<variables>]]" >&2; exit 64; }
sql() { docker exec -i "$PG" psql -U postgres -d integrations_db -At -v ON_ERROR_STOP=1 -c "$1"; }

case "${1:-}" in
  up)
    docker network inspect "$NET" >/dev/null 2>&1 || docker network create "$NET" >/dev/null
    docker rm -f "$PG" >/dev/null 2>&1 || true
    docker run -d --name "$PG" --network "$NET" -e POSTGRES_PASSWORD=password \
      -e POSTGRES_DB=integrations_db "$PG_IMAGE" >/dev/null
    # The init server listens on the socket only: wait for TCP, i.e. the final server.
    for _ in $(seq 1 60); do
      docker exec "$PG" pg_isready -h 127.0.0.1 -U postgres -d integrations_db >/dev/null 2>&1 && break
      sleep 1
    done
    docker exec "$PG" pg_isready -h 127.0.0.1 -U postgres -d integrations_db >/dev/null \
      || { echo "ERROR: PostgreSQL not ready" >&2; exit 1; }
    docker run --rm --network "$NET" -v "$REPO/db/liquibase:/liquibase/changelog:ro" "$LB_IMAGE" \
      --url="jdbc:postgresql://$PG:5432/integrations_db" --username=postgres --password=password \
      --search-path=/liquibase/changelog --changelog-file=master.xml update >/dev/null
    docker exec -i "$PG" psql -U postgres -d integrations_db -q -v ON_ERROR_STOP=1 \
      < "$HERE/fixtures/processes.sql"
    echo "OK lab up"
    ;;
  down)
    docker rm -f "$PG" >/dev/null 2>&1 || true
    docker network rm "$NET" >/dev/null 2>&1 || true
    rm -rf "$WORK"
    echo "OK lab down"
    ;;
  copy)
    rm -rf "$WORK/copy"
    mkdir -p "$WORK/copy"
    # Tracked and untracked (not ignored) files of the working tree, as they are now.
    (cd "$REPO" && git ls-files -z --cached --others --exclude-standard \
      | tar --null --ignore-failed-read -T - -cf -) | tar -x -C "$WORK/copy"
    for p in vartest uuidtest; do
      mkdir -p "$WORK/copy/src/project/main/$p"
      cp "$HERE/fixtures/start.hwf" "$WORK/copy/src/project/main/$p/start.hwf"
    done
    mkdir -p "$WORK/copy/logs" "$WORK/copy/temp"
    echo "OK copy $WORK/copy"
    ;;
  sql)
    [[ $# -eq 2 ]] || usage
    sql "$2"
    ;;
  run)
    [[ $# -ge 3 && $# -le 5 ]] || usage
    ver="$2" file="$3" params="${4:-}" vars="${5:-}"
    mkdir -p "$WORK"
    set +e
    docker run --rm --network "$NET" --user "$(id -u):$(id -g)" \
      -e HOME=/tmp -e HOP_CONFIG_FOLDER=/tmp/hop-config -e HOP_AUDIT_FOLDER=/tmp/hop-audit \
      -v "$WORK/copy:/project" -v "$HERE:/tests:ro" \
      --entrypoint /bin/bash "apache/hop:$ver" /tests/entry.sh "$file" "$params" "$vars" \
      > "$WORK/hoprun.log" 2>&1
    rc=$?
    set -e
    echo "RC=$rc"
    ;;
  *) usage ;;
esac
~~~

- [ ] **Step 2: Write `tests/hop/entry.sh`**

~~~bash
#!/usr/bin/env bash
# Runs inside an apache/hop container (see tests/hop/lab.sh run): registers the
# project "tpl" (/project) and the environment "lab" (template files + lab
# overrides), then runs hop-run. Exit code: the one of hop-run, 2 if the
# registration fails.
# Usage: entry.sh <file relative to /project> <params or ""> <variables or "">
set -uo pipefail
file="$1" params="${2:-}" vars="${3:-}"
/opt/hop/hop-conf.sh -pc -p tpl -ph /project >/dev/null || exit 2
/opt/hop/hop-conf.sh -ec -e lab -ep tpl \
  -eg /project/config/template-env.json,/project/config/template-postgresql.json,/tests/lab-env.json \
  >/dev/null || exit 2
args=(-j tpl -e lab -r local -f "/project/$file")
[[ -n "$params" ]] && args+=(-p "$params")
[[ -n "$vars" ]] && args+=(-s "$vars")
/opt/hop/hop-run.sh "${args[@]}"
~~~

~~~bash
#!/usr/bin/env bash
# Scenario checks of the template workflows on one Hop version (spec "Testing").
# Prerequisite: tests/hop/lab.sh up. Makes a fresh copy of the working tree first.
# Usage: tests/hop/scenarios.sh <hop version>   (exit 1 if a check failed)
set -uo pipefail
unset CDPATH
HERE="$(cd "$(dirname "$0")" && pwd -P)"
LAB="$HERE/lab.sh"
LOG="$HERE/work/hoprun.log"
COPY="$HERE/work/copy"
VER="${1:?usage: tests/hop/scenarios.sh <hop version>}"
failed=0

check() { # check <description> <command...>
  if "${@:2}"; then echo "  ok   $1"; else echo "  FAIL $1"; failed=1; fi
}
run() { RC="$("$LAB" run "$VER" "$@" | sed -n 's/^RC=//p')"; }
rc_is() { [[ "$RC" == "$1" ]]; }
log_has() { grep -qF -- "$1" "$LOG"; }
log_lacks() { ! grep -qF -- "$1" "$LOG"; }
sql_is() { [[ "$("$LAB" sql "$1")" == "$2" ]]; }
marker_is() { [[ "$(cat "$COPY/temp/result" 2>/dev/null)" == "$1" ]]; }
reset() {
  "$LAB" sql "UPDATE config.integrations_processes SET is_running='N', is_active='Y'" >/dev/null
  rm -f "$COPY"/config/*.properties "$COPY/temp/result"
}

s_default() {
  echo "default process"
  reset
  run main.hwf "p_base_process_name=default"
  check "exit code 0" rc_is 0
  check "last run of default is T" sql_is \
    "SELECT proc_status FROM logs.integrations_logs WHERE integrations_processes_id='default' ORDER BY date_started DESC LIMIT 1" T
  check "lock released" sql_is "SELECT is_running FROM config.integrations_processes WHERE short_name='default'" N
}

s_regression() {
  echo "regression: paused, locked, result marker"
  reset
  "$LAB" sql "UPDATE config.integrations_processes SET is_active='N' WHERE short_name='default'" >/dev/null
  run main.hwf "p_base_process_name=default" "SERASOFT_RESULT_FILE=/project/temp/result"
  check "paused: exit code 1" rc_is 1
  check "paused: marker skipped_paused" marker_is skipped_paused
  reset
  "$LAB" sql "UPDATE config.integrations_processes SET is_running='Y' WHERE short_name='default'" >/dev/null
  run main.hwf "p_base_process_name=default" "SERASOFT_RESULT_FILE=/project/temp/result"
  check "locked: exit code 1" rc_is 1
  check "locked: marker skipped_locked" marker_is skipped_locked
  check "locked: SKIPPED message" log_has "SKIPPED: process 'default' is locked"
  reset
}

SCENARIOS=(s_default s_regression)

"$LAB" copy >/dev/null
for s in "${SCENARIOS[@]}"; do "$s"; done
if [[ $failed -eq 0 ]]; then echo "OK scenarios hop=$VER"; else echo "FAILED scenarios hop=$VER"; exit 1; fi
~~~

~~~markdown
## Process parameters (`p_process_params`)

`main.hwf` declares only the template parameters: `p_base_process_name`, `p_log_filename` and `p_process_params`. Hop silently ignores a `-p` value for a parameter the workflow does not declare, so the values specific to a process are passed through `p_process_params`:

```
hop-run -j <project> -e <environment> -r local -f '${PROJECT_HOME}/main.hwf' \
  -p 'p_base_process_name=<short name>,p_process_params=p_period_type=S;p_reference_date=20261031'
```

- **Format**: `key=value` pairs separated by `;`. Spaces around keys and values are removed, empty pairs (for example a trailing `;`) are ignored, and the value is everything after the first `=` (`p_filter=a=b` gives `a=b`).
- **Limits**: a value cannot contain `;` (the pair separator) or `,` (`hop-run -p` separates parameters with commas).
- **Keys** must match `^[A-Za-z_][A-Za-z0-9_.]*$` and appear once.
- Each pair becomes a **variable of the root workflow**: `start.hwf` and everything it runs see it as `${key}`. The pre-phase logs the names of the keys it set (`p_process_params: set p_period_type, p_reference_date`), never their values.
- **Precedence** (the last one wins): environment files → `config/<short name>.properties` → `p_process_params`. Put the defaults of a process in its `.properties` file and override them per execution with `p_process_params`.
- **Errors**: an invalid entry stops the execution in the pre-phase, before the process starts, with exit code `1` and the message `ERROR: invalid p_process_params entry '<entry>': <reason>`, where the reason is `missing '='`, `invalid key '<key>'` or `key '<key>' given more than once`.
- **Do not declare these keys as parameters** of `start.hwf` or of the workflows and pipelines it runs: since Hop 2.20 a declared parameter with a default ignores a variable of the same name set by the caller (apache/hop#8101), so the value passed in `p_process_params` would be lost. Use them as plain variables.

From cron, quote the whole `-p` value so that the shell does not split it on `;`:

```
0 6 * * * /opt/hop/hop-run.sh -j myproject -e prod -r local -f '${PROJECT_HOME}/main.hwf' -p 'p_base_process_name=load_sales,p_process_params=p_period_type=M'
```

From an orchestrator (e.g. Apache Airflow), pass `p_process_params` like any other `-p` parameter of `main.hwf`.

## Environments

The environment of a template-based project is a list of configuration files read in this order, a later file overriding an earlier one:

1. `config/template-env.json`: the template variables and their defaults (template-owned, never edited);
2. `config/template-<database>.json`, with `<database>` one of `postgresql`, `mssql`, `sqlite` (template-owned, never edited);
3. one project file per environment, e.g. `config/<project>-<environment>-env.json`: the project's own variables and the real values of the `serasoft.*` variables for that environment (database host and credentials, SMTP, mail addresses). Keep the files with credentials out of Git.

```
hop-conf.sh -ec -e prod -ep myproject \
  -eg /opt/projects/myproject/config/template-env.json,/opt/projects/myproject/config/template-postgresql.json,/etc/hop/myproject-prod-env.json
```

Never add project variables to the template files: `tools/serasoft-sync.sh` overwrites them at every template update and `tools/serasoft-verify.sh` reports them as modified.
~~~

~~~bash
#!/usr/bin/env bash
# Checks the template-owned files of a Hop project: run from the project root,
# by its CI or by hand. Fails if a file listed in SERASOFT_MANIFEST.sha256 was
# modified or removed, if src/template/ or db/liquibase/ hold a file or symlink
# not listed there (or are themselves symlinks), or if SERASOFT_VERSION is
# missing or empty. The SQLite seed files (db/sqlite/data/) are not checked.
# These files come from SeraSoft/hop-process-template via tools/serasoft-sync.sh:
# change them in the template, never here (README.md, "Template updates").
set -euo pipefail

MANIFEST=SERASOFT_MANIFEST.sha256
OWNED_DIRS=(src/template db/liquibase)

[[ $# -eq 0 ]] || { echo "usage: tools/serasoft-verify.sh (from the project root)" >&2; exit 64; }
[[ -f "$MANIFEST" ]] || { echo "ERROR: $MANIFEST not found: run from the project root" >&2; exit 66; }

failed=0

# --strict: an improperly formatted line fails instead of being skipped.
if ! check="$(sha256sum --check --strict "$MANIFEST" 2>&1)"; then
  echo "ERROR: template files modified or removed:" >&2
  grep -v ': OK$' <<<"$check" >&2 || true
  failed=1
fi

for dir in "${OWNED_DIRS[@]}"; do
  if [[ -L "$dir" ]]; then
    echo "ERROR: $dir is a symlink, not the template directory" >&2
    failed=1
  fi
done

# sha256sum accepts CRLF lines: strip the \r here too.
listed="$(sed -E 's/^[0-9a-f]{64} [ *]//; s/\r$//' "$MANIFEST" | LC_ALL=C sort)"
present="$( { find "${OWNED_DIRS[@]}" ! -type d 2>/dev/null || true; } | LC_ALL=C sort)"
extra="$(LC_ALL=C comm -13 <(printf '%s\n' "$listed") <(printf '%s\n' "$present") | sed '/^$/d')"
if [[ -n "$extra" ]]; then
  echo "ERROR: files not from the template in ${OWNED_DIRS[*]}:" >&2
  printf '%s\n' "$extra" >&2
  failed=1
fi

version="$(head -n1 SERASOFT_VERSION 2>/dev/null || true)"
version="${version%$'\r'}"
if [[ -z "${version//[[:space:]]/}" ]]; then
  echo "ERROR: SERASOFT_VERSION missing or empty: run tools/serasoft-sync.sh" >&2
  failed=1
fi

[[ "$failed" -eq 0 ]] || exit 1
echo "OK serasoft-verify version=${version%% *} files=$(grep -c . "$MANIFEST")"
~~~

~~~bash
#!/usr/bin/env bash
# Copies the template-owned files of hop-process-template, as of an annotated
# release tag, into a Hop project repository, and rewrites SERASOFT_VERSION and
# SERASOFT_MANIFEST.sha256 there. Run from a checkout of hop-process-template
# that has the tag. It does not commit: review the diff, commit, open the PR/MR
# (README.md, "Template updates").
#
# Usage: tools/serasoft-sync.sh --tag <X.Y.Z> --dest <project repository>
set -euo pipefail

MANIFEST=SERASOFT_MANIFEST.sha256
SEEDS=(db/sqlite/data/integrations_db db/sqlite/data/integrations_db.config db/sqlite/data/integrations_db.logs)
LIQUIBASE=db/liquibase/master.xml

usage() {
  echo "usage: tools/serasoft-sync.sh --tag <X.Y.Z> --dest <project repository>" >&2
  exit 64
}
die() { echo "ERROR: $*" >&2; exit 1; }
warn() { echo "WARNING: $*" >&2; }

tag="" dest=""
while [[ $# -gt 0 ]]; do
  [[ $# -ge 2 ]] || usage
  case "$1" in
    --tag)  tag="$2" ;;
    --dest) dest="$2" ;;
    *)      usage ;;
  esac
  shift 2
done
[[ -n "$tag" && -n "$dest" ]] || usage

unset CDPATH
upstream="$(git -C "$(dirname "$0")" rev-parse --show-toplevel)"
commit="$(git -C "$upstream" rev-parse --verify --quiet "refs/tags/$tag^{commit}")" \
  || die "tag $tag not found in $upstream (git fetch --tags?)"
[[ "$(git -C "$upstream" cat-file -t "refs/tags/$tag")" == tag ]] \
  || die "tag $tag is not annotated (release notes are in the annotated tag message)"

[[ -d "$dest" ]] || die "$dest is not a directory"
dest="$(cd "$dest" && pwd -P)"
[[ "$(git -C "$dest" rev-parse --show-toplevel 2>/dev/null)" == "$dest" ]] \
  || die "$dest is not the root of a Git work tree"
[[ "$dest" != "$(cd "$upstream" && pwd -P)" ]] || die "--dest is the template itself"
[[ -z "$(git -C "$dest" status --porcelain)" ]] || die "$dest has uncommitted changes"

# Template-owned paths, as named in the project (spec A3, "Ownership").
owned_path() {
  [[ "/$1/" != */../* && "$1" != */ ]] || return 1
  case "$1" in
    main.hwf|tools/serasoft-verify.sh) return 0 ;;
    src/template/*|db/liquibase/*) return 0 ;;
    config/template-*.json) [[ "$1" != config/*/* ]] ;;
    metadata/rdbms/integrations_db_*.json) [[ "$1" != metadata/rdbms/*/* ]] ;;
    metadata/workflow-log/workflow_log.json) return 0 ;;
    metadata/pipeline-run-configuration/local.json) return 0 ;;
    metadata/workflow-run-configuration/local.json) return 0 ;;
    *) return 1 ;;
  esac
}
# Before 2.1.0 the environment files were config/default-*.json (#20).
legacy_owned_path() {
  owned_path "$1" || { [[ "$1" == config/default-*.json && "$1" != config/*/* ]]; }
}
is_seed() { local s; for s in "${SEEDS[@]}"; do [[ "$1" == "$s" ]] && return 0; done; return 1; }

# tag_files <commit> <legacy 0|1>: the template-owned and seed files of a commit,
# one line "<path in commit>\t<path in project>" each; the root README.md is
# shipped as src/template/README.md.
tag_files() {
  local f
  while IFS= read -r -d '' f; do
    [[ "$f" != *\\* && "$f" != *$'\n'* && "$f" != *$'\t'* ]] \
      || die "$1 has a file name with a backslash, a tab or a newline: ${f@Q}"
    [[ "$f" != src/template/README.md ]] || die "$1 has src/template/README.md (reserved for the shipped README.md)"
    if [[ "$f" == README.md ]]; then
      printf '%s\t%s\n' "$f" src/template/README.md
    elif is_seed "$f" || { [[ "$2" == 1 ]] && legacy_owned_path "$f"; } || owned_path "$f"; then
      printf '%s\t%s\n' "$f" "$f"
    fi
  done < <(git -C "$upstream" ls-tree -r -z --name-only "$1")
}

# extract <commit> <dir>: the files of tag_files <commit> 0, under their project names.
extract() {
  local listing s p
  local -a src=()
  listing="$(tag_files "$1" 0)" || exit 1
  while IFS=$'\t' read -r s p; do [[ -n "$s" ]] && src+=("$s"); done <<<"$listing"
  [[ ${#src[@]} -gt 0 ]] || die "no template file in $1"
  mkdir -p "$2"
  { git -C "$upstream" archive "$1" -- "${src[@]}" | tar -x -C "$2"; } \
    || die "cannot extract the template files from $1"
  if [[ -f "$2/README.md" ]]; then
    mkdir -p "$2/src/template"
    mv "$2/README.md" "$2/src/template/README.md"
  fi
}

remove() {
  rm -f "$dest/$1"
  (cd "$dest" && rmdir -p --ignore-fail-on-non-empty "$(dirname "$1")" 2>/dev/null) || true
}

tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT
extract "$commit" "$tmp/new"
new=() seeds=()
while IFS= read -r -d '' f; do
  f="${f#./}"
  if is_seed "$f"; then seeds+=("$f"); else new+=("$f"); fi
done < <(cd "$tmp/new" && find . -type f -print0 | LC_ALL=C sort -z)
declare -A in_new=()
for f in "${new[@]}"; do in_new["$f"]=1; done

# The previous manifest drives the removals: check it before writing anything,
# so that a damaged one can never remove a project file.
old=()
declare -A old_sum=()
if [[ -f "$dest/$MANIFEST" ]]; then
  while IFS= read -r line; do
    line="${line%$'\r'}"
    { [[ "$line" =~ ^([0-9a-f]{64})\ [\ *](.+)$ ]] && owned_path "${BASH_REMATCH[2]}"; } \
      || die "$MANIFEST in $dest: not a template-owned entry: $line"
    old+=("${BASH_REMATCH[2]}")
    old_sum["${BASH_REMATCH[2]}"]="${BASH_REMATCH[1]}"
  done < "$dest/$MANIFEST"
fi
declare -A in_old=()
for f in "${old[@]}"; do in_old["$f"]=1; done

added=0 changed=0 removed=0 adopted=0 forced=0
declare -A adopt_rm=()

# Never overwrite a project file. With a previous manifest, a template file of
# the new version may already exist only if that manifest lists it. On a first
# sync, no template file may exist yet, and the owned directories must be empty.
if [[ -f "$dest/$MANIFEST" ]]; then
  clash=()
  for f in "${new[@]}"; do
    [[ -e "$dest/$f" || -L "$dest/$f" ]] || continue
    [[ -n "${in_old[$f]:-}" ]] || clash+=("$f")
  done
  [[ ${#clash[@]} -eq 0 ]] || die "files of $tag already in $dest and not from the template: ${clash[*]}"
  if [[ -n "${old_sum[$LIQUIBASE]:-}" && -f "$tmp/new/$LIQUIBASE" ]] \
      && [[ "$(sha256sum < "$tmp/new/$LIQUIBASE" | cut -d' ' -f1)" != "${old_sum[$LIQUIBASE]}" ]]; then
    warn "$LIQUIBASE changed: run liquibase update on the project databases (src/template/README.md, \"Support database creation\")"
  fi
else
  clash=()
  for f in "${new[@]}"; do
    [[ -e "$dest/$f" || -L "$dest/$f" ]] && clash+=("$f")
  done
  while IFS= read -r -d '' f; do
    f="${f#./}"
    [[ -n "${in_new[$f]:-}" ]] || clash+=("$f")
  done < <(cd "$dest" && { find ./src/template ./db/liquibase ! -type d -print0 2>/dev/null || true; } | LC_ALL=C sort -z)
  [[ ${#clash[@]} -eq 0 ]] \
    || die "no $MANIFEST in $dest, and template files already there: ${clash[*]} (a project that already holds template files: use --adopt-from <tag|auto>)"
fi

for f in "${new[@]}"; do
  if [[ ! -e "$dest/$f" ]]; then
    added=$((added + 1))
  elif ! cmp -s "$tmp/new/$f" "$dest/$f" \
      || [[ "$(stat -c %a "$tmp/new/$f")" != "$(stat -c %a "$dest/$f")" ]]; then
    changed=$((changed + 1))
  fi
done
for f in "${old[@]}"; do
  if [[ -z "${in_new[$f]:-}" ]] && [[ -e "$dest/$f" || -L "$dest/$f" ]]; then
    remove "$f"
    removed=$((removed + 1))
  fi
done
for f in "${!adopt_rm[@]}"; do
  remove "$f"
  removed=$((removed + 1))
done

# Only the files: a "." entry would give $dest the 0700 mode of $tmp.
(cd "$tmp/new" && tar -cf - -- "${new[@]}") | tar -x -C "$dest"
for f in "${seeds[@]}"; do
  if [[ -e "$dest/$f" ]]; then
    cmp -s "$tmp/new/$f" "$dest/$f" || warn "kept local $f (SQLite seed file: never overwritten)"
  else
    (cd "$tmp/new" && tar -cf - -- "$f") | tar -x -C "$dest"
    added=$((added + 1))
  fi
done
(cd "$dest" && sha256sum -- "${new[@]}") > "$dest/$MANIFEST"
printf '%s %s\n' "$tag" "$commit" > "$dest/SERASOFT_VERSION"

echo "OK serasoft-sync tag=$tag commit=${commit:0:12} added=$added changed=$changed removed=$removed adopted=$adopted forced=$forced"
~~~

~~~markdown
## Template updates

A project gets the template files from an **annotated release tag** of hop-process-template with `tools/serasoft-sync.sh`, and checks them with `tools/serasoft-verify.sh`. The project does not share the template's Git history.

### Who owns what

| Category | Paths | Sync | Verify |
|---|---|---|---|
| Template | `main.hwf`, `src/template/**`, `config/template-*.json`, `metadata/rdbms/integrations_db_*.json`, `metadata/workflow-log/workflow_log.json`, `metadata/pipeline-run-configuration/local.json`, `metadata/workflow-run-configuration/local.json`, `db/liquibase/**`, `tools/serasoft-verify.sh`, and this README as `src/template/README.md` | copied, overwritten | checked |
| SQLite seed | `db/sqlite/data/integrations_db`, `integrations_db.config`, `integrations_db.logs` | copied only when missing, never overwritten | not checked |
| Project | everything else: `src/project/**`, `config/project-config.json`, the project environment files, `README.md`, `.gitignore`, … | never touched | not checked |

Two files at the root of the project record the version: `SERASOFT_VERSION` (`<tag> <commit>`) and `SERASOFT_MANIFEST.sha256` (one `sha256sum` line per template file).

### Creating or updating a project

From a checkout of hop-process-template with the tags (`git fetch --tags`), on a clean checkout of the project (a dedicated branch, e.g. `template/3.2.0`):

```
tools/serasoft-sync.sh --tag 3.2.0 --dest ../myproject
```

The sync:

- refuses an unknown or lightweight tag, a destination that is not the root of a Git work tree or has uncommitted changes;
- copies the template files from the tag (never from the working copy), refusing to overwrite a project file: a template file may already exist in the project only if the previous manifest lists it;
- removes the template files of the previous version that the new one no longer has;
- copies the SQLite seed files only when missing, and prints `WARNING: kept local <file>` when a local one differs;
- prints `WARNING: db/liquibase/master.xml changed: run liquibase update …` when the database changelog changed: update every project database (see "Support database creation");
- rewrites `SERASOFT_VERSION` and `SERASOFT_MANIFEST.sha256` and prints `OK serasoft-sync tag=… commit=… added=… changed=… removed=… adopted=… forced=…`.

It does not commit: review the diff, commit (e.g. `Template 3.2.0`), open the pull/merge request with the release notes of the tag (`git tag -n99 3.2.0` in the template).

### Checking a project

From the project root, by hand or in its CI:

```
tools/serasoft-verify.sh
```

It fails (exit code `1`, offending files listed) when a template file was modified or removed, when `src/template/` or `db/liquibase/` hold a file the manifest does not list (or are symlinks), or when `SERASOFT_VERSION` is missing or empty. A GitLab CI job:

```yaml
serasoft-verify:
  image: alpine:3.20
  script:
    - apk add --no-cache bash coreutils
    - tools/serasoft-verify.sh
```

Recommended in the project repository:

- a code-owner or approval rule on `main.hwf`, `src/template/`, `config/template-*.json`, `db/liquibase/`, `metadata/` and `SERASOFT_*`, so that template files change only through a template update;
- a `.gitattributes` keeping the template files with LF line endings (with `core.autocrlf=true` a Windows checkout converts them to CRLF and a local verify fails):

  ```
  *.hwf  text eol=lf
  *.hpl  text eol=lf
  *.json text eol=lf
  *.xml  text eol=lf
  *.sh   text eol=lf
  SERASOFT_* text eol=lf
  ```

- a `.gitignore` with at least `logs/`, `temp/` and the environment files that hold credentials.
~~~

~~~bash
# pick_adopt_tag: sets adopt_from to the tag with the most template-owned files
# identical to $dest (the most recent one on a tie).
pick_adopt_tag() {
  local t c s p n m listing best="" best_n=0 best_m=0
  while IFS= read -r t; do
    c="$(git -C "$upstream" rev-parse --verify --quiet "refs/tags/$t^{commit}")" || continue
    listing="$(tag_files "$c" 1)" || exit 1
    n=0 m=0
    while IFS=$'\t' read -r s p; do
      [[ -n "$s" ]] || continue
      is_seed "$p" && continue
      m=$((m + 1))
      if [[ -f "$dest/$p" ]] && git -C "$upstream" cat-file blob "$c:$s" | cmp -s - "$dest/$p"; then
        n=$((n + 1))
      fi
    done <<<"$listing"
    if (( n > 0 && n >= best_n )); then best="$t" best_n=$n best_m=$m; fi
  done < <(git -C "$upstream" for-each-ref --sort=creatordate --format='%(refname:short)' refs/tags)
  [[ -n "$best" ]] || die "--adopt-from auto: no tag has a template file identical to $dest"
  echo "adopt-from auto: $best ($best_n/$best_m files identical)" >&2
  adopt_from="$best"
}
~~~

~~~markdown
### Adopting a project that already holds template files

A project created before the sync existed (template 2.x copied by hand, or a 1.0.x project after its migration) has template files but no `SERASOFT_MANIFEST.sha256`: the plain sync refuses it. Give the version the project starts from:
~~~
